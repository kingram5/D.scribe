## Fixes

- Live startup now checks its lifecycle generation after microphone acquisition,
  SDP preparation and session start. Late microphone streams stop immediately;
  a session allocated after departure receives an explicit stop request using
  its returned ID. An abandoned startup never installs a heartbeat. The start
  request is deliberately not aborted, so a returned session ID can be closed.
- Typed answers have a synchronous in-flight lock and a disabled pending button.
  Network and HTTP failures retain the text and show a retry message. Successful
  saves clear only the submitted revision, preserving writing entered while a
  save was pending, including after remount.
- A run-scoped sessionStorage recovery copy retains unsaved writing and its
  question/follow-up context across refresh and remount in the same tab. It is
  not a server autosave or cross-device backup. Storage failure keeps the text
  in memory and explains that the tab must remain open until it is saved.
- Dashboard filter tabs use roving focus/selection with Left/Right wrapping and
  Home/End. New-project title has a visible associated label. Live controls have
  explicit 44px minimum touch targets and a 16px textarea.
- All 18 repository ESLint errors are resolved without rule suppression. Browser
  hydration and media state use stable external snapshots; derived prop resets
  no longer run in effects. Stored progress is not overwritten during hydration
  or carried between projects. Wordmark IDs use React IDs; the animation's
  paused ref updates in an effect. The SDK inspection script uses ESM imports.
  CI selects Node 24 to match the documented runtime and DOM test requirements,
  and runs blocking lint/type checks.
- Layout fonts and the landing page's decorative Cormorant Garamond are vendored
  from Fontsource 5.3.0. Builds and browser typography no longer request Google
  Fonts. Unicode ranges, styles and variable weights are retained; each family's
  OFL license, provenance and file hashes are in `public/fonts/`.
